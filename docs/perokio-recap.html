What it is

A payout event, not a content app

Creators compete for real cash prizes. You vote on who wins. Brands fund the pool, creators submit content, blind peer voting narrows the field, and the public picks the winner — escrowed with Stripe, paid out when the round closes.

The product is not a content app with a payout feature. It is a payout event that generates content, spectators, and its own marketing.

The funnel & economics

Three elimination rounds, one escrowed pool

This is the mechanic every page in the app ultimately serves — a creator's content moves through three rounds, narrowing by blind vote each time, until one winner and twelve others walk away with money.

Round 1
Teaser
≤15s clip. Blind pairwise voting — two anonymised teasers side by side, never one alone. Picking blocked for the first 3s. A voter must cast 8 votes before their own result unlocks.
→
Round 2
Full content
Survivors produce the complete piece. Peer voting narrows the field down to a final four.
→
Round 3
Public final
Blind verified-audience vote. The brand makes the final call between the top contenders.

Where a $5,000 pool actually goes

ComponentFormulaAt $5,000
Winner prizethe pool$5,000
Finalist stipends12% of pool, 4 ways$150 each
Round-2 survivor bonus6% of pool across survivors$25 each
Crowd favourite5% of pool, floor $50 — platform-funded$250
Platform fee20% gross → 10.2% net after bonus + Stripe$1,180 → $724

Two currencies keep the growth loop from corrupting the contest: quality score (blind votes from a pool untouched by the competing creator's own link) decides the prize; rally score (votes from a creator's own link) earns XP and the crowd-favourite bonus, never the prize itself.

What's actually built

Shipped, not planned

Pulled straight from the sprint log in TODO.md — this is what's real today, not a roadmap.

Backend spine

  • Full competition/escrow/voting/trust/growth schema
  • Stripe Connect escrow + all 4 payout types
  • Mux video upload/playback
  • Phone-OTP identity
  • BullMQ round state machine (open → closed → tallied → revealed)

Competition core

  • Blind pairwise voting with 3s gate + attention check
  • 8-vote participation gate
  • Brand light-score + composite (70/30 peer/brand)
  • Round-3 seller final pick, auto-falls back to top quality vote

Growth loops

  • Personal rally links + live voter counter + rally XP
  • Share cards (advance/knockout/win) via next/og
  • Public no-login SSR spectator pages, cached + rate-limited
  • Referrals — signup attribution, $5 reward on first submit/vote

Retention & social proof

  • Tiers end-to-end (badge on profile/entry/OG image)
  • Voting streaks — pause, not break
  • Discovery feed (creators/brands tabs)
  • Creator Journey — 6 milestones, /me stepper

Money & trust

  • Wallet summary + bidirectional ratings
  • Public brand trust stats (ADR-004)
  • KYB gate (admin-reviewed) on funding
  • Server-derived round scheduling

Brand tools

  • Funding wizard — auto-opens round 1 on webhook confirm
  • Campaign analytics (funnel, votes, payouts by type)
  • Invite creators from discovery + notification

Admin & ops

  • God-view console, stuck-round detection + force-reveal
  • KYB approve/reject queue, dispute raise + resolve
  • Growth dashboard (completion rate, repeat rate, k-proxy)

Platform

  • PWA — manifest, service worker, install prompt
  • In-app notification inbox, real per-event copy
  • Story/Claim model — generalizes Challenge to free (unfunded) briefs
  • Docker prod stack — Postgres, Redis, api, web, Caddy TLS

Deliberately stubbed or cut — not silently dropped

  • AI image/video generation — needs a Fal.ai/Replicate key
  • KYC document verification — admin flag only, not real Stripe Identity
  • Push/SMS/email delivery — in-app inbox only, needs FCM/Twilio/SES
  • GPS geofencing — QR-code check-in instead (this is a web app)
  • Coordinated vote-fraud detection — cut, needs real voting data to tune
  • Native mobile app — replaced by an installable PWA on purpose
  • Ad-based streak recovery — no ad SDK, streak auto-resumes instead
What's left

Gating a real launch

In order — none of these are "more features," they're what stands between this and going live.

Launch blocker

Sweepstakes/gambling exposure — unresolved. Entry must be free and the outcome defensible as skill-determined; the peer-vote mechanic needs to survive that test jurisdiction by jurisdiction. Blocks both the Terms of Service and the payout logic. Get a legal opinion in parallel with everything else — it's the longest pole, not a code task.

  • Provider accounts moving sandbox → live (Stripe Connect, Mux, Twilio Verify) — mostly account-review time
  • Sprint 5 depth work — predictions, in-person campaigns, real AI creative studio
  • Load/concurrency testing on the round state machine — the docs call it "the crux"; a bug here is a wrong contest result, not a UI glitch
  • Cold-start execution — 10 local brands + 50 hand-recruited creators, calendar time not code
